# Как Tapik отправляет зашифрованное сообщение

Телефон отправителя шифрует сообщение и подписывает запрос. Сервер видит отправителя, адресатов и зашифрованные пакеты. Для доставки ему не нужен секретный ключ устройства. Этот документ описывает серверную часть.

## Путь одного сообщения

1. Клиент отправляет подписанный запрос в `POST /chats/messages` через Nginx. ChatService получает идентификатор пользователя из JWT и обращается к внутреннему writer.
2. Writer проверяет состав чата, активность устройств, подпись и набор получателей. Для группы он также проверяет версию состава и зарегистрированную раздачу Sender Key.
3. Writer фиксирует решение принять отправку. Внутренняя квитанция связывает операцию с отправителем, отпечатком запроса и версией состава. По ней можно закончить работу после перезапуска.
4. Writer обеспечивает наличие задачи доставки в Scylla, сохраняет сообщение в истории и подтверждает завершение записи. Клиент получает квитанцию.
5. Фоновый обработчик публикует событие в RabbitMQ. ChatService проверяет актуальный доступ и сообщает подключённым устройствам по WebSocket о новом сообщении. Получатель запрашивает данные через HTTP. Офлайн-устройство может догрузить историю позже.

## Что означает квитанция

| Поле | Значение для клиента |
|---|---|
| `chatId`, `messageId` | По этой паре можно запросить сохранённое сообщение |
| `chatSeq` | Позиция в общей истории чата |
| `messageHash` | Отпечаток подписанных данных сообщения |
| `chainHash` | Отпечаток цепочки истории на этой позиции |
| `replayed` | Writer использовал уже зарегистрированную операцию |

Допустим, телефон отправил запрос с номером устройства `seq = 17`, а сервер присвоил сообщению позицию `chatSeq = 42`. Если ответ потерялся, телефон повторяет тот же подписанный запрос с номером 17. Сервер возвращает прежний идентификатор сообщения и позицию 42. Попытка использовать тот же номер для другого содержимого приводит к конфликту. Квитанция подтверждает сохранение на сервере. Для статуса прочтения нужны отдельные данные от получателя.

## Outbox и два фоновых обработчика

Outbox — таблица незавершённых задач доставки `e2e_delivery_pending`. В задаче хранятся ссылки на операцию и сообщение. Сама история хранится отдельно.

| Ситуация | Поведение |
|---|---|
| Отправка принята, запись прервалась | Recovery worker повторно открывает принятую операцию и завершает запись |
| Сообщение сохранено, RabbitMQ недоступен | Операция остаётся `COMMITTED`, доставка остаётся `PENDING` |
| Брокер подтвердил публикацию | Delivery worker отмечает `PUBLISHED` и удаляет задачу из outbox |
| Worker упал после публикации, до отметки в базе | Возможен повтор события с тем же `eventId`. Клиент может объединить повторы по `messageId` |
| Worker упал после отметки, до удаления задачи | При следующей обработке он удаляет завершённую задачу |

Сигнал `message.e2e.available` содержит идентификаторы и позицию в чате. Устройство получает сообщение через `GET /chats/:chatId/e2e/messages/:messageId`. Для синхронизации истории используется `GET /chats/:chatId/e2e/messages`.

## Группы и отзыв доступа

В личном чате отправитель готовит отдельный пакет для каждого устройства-получателя. В группе он сначала распространяет свой Sender Key по устройствам, затем отправляет групповые сообщения. После изменения состава прежняя версия состава отклоняется. Исключённый участник теряет доступ к серверной истории. Данные, уже сохранённые на его устройстве, остаются у него. После отзыва устройства новые отправки с него отклоняются. Операция, прошедшая проверку до отзыва, может завершиться.

## Как проверить

Из каталога ChatService команда `npm test -- --runInBand --watchman=false` запускает тесты Jest. Команда `sh test/integration/scylla-test.sh` поднимает одноразовую Scylla в Docker и проверяет конкурентные отправки и историю. Команда `node test/integration/sender-keys.mjs` проверяет смену группового ключа с библиотекой Signal.

В полном рабочем каталоге Tapik при запущенном локальном стенде общий прогон запускается командой `./scripts/test-e2ee.sh` из родительской папки. Он включает проверку через Nginx с временными аккаунтами.
